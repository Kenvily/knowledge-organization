# EvoAgent 面试速查表

> 2026-09-14 · `develop / a5b880f` 及当前工作区。用于面试前快速复习，完整版见 [项目学习与面试指南](PROJECT_LEARNING_GUIDE.md)。下文明确区分当前能力和扩展建议；保留图表为人工情景，不能作为真实收益证明。

## 1 一句话与架构

**一句话：** EvoAgent 是面向数据分析与运维诊断的可治理 Agent Harness，让模型在权限和预算内执行任务，再将反馈转化为可评测、可审批、可回滚的方法更新。

```text
用户问题、标签、范围、Skill 选择
  → FastAPI：身份 / CSRF / 参数 / 资源
  → 规则路由 → Task 持久化 → Runtime
  → 基础：Schema → 口径检索 → SQL 规划 → 只读执行 → 报告
    或调查：规划 → 受控工具 → 观测 / 检查点 → 再规划 → 结束
  → 轨迹、确定性评价、费用与线上使用记录

管理员选任务 → 规则/LLM 提炼经验 → 设预算、目标和父版
  → Skill 候选 → 来源评测 / 可选分类评测
  → 管理员发布或拒绝 → 后续任务检索生产版
```

**技术栈：** FastAPI、LangGraph、SQLAlchemy/PostgreSQL、httpx/DeepSeek、stdio MCP、本地哈希向量/FAISS、原生 JS。

**重要边界：** 当前主链是共享单规划器循环，不是自主多 Agent 团队。API 可并发接收，但同库在线 Runtime 用锁保持单工作进程、顺序执行；Redis 只参与就绪检查，不是任务队列。离线批次另行异步运行。

## 2 六个核心概念

| 概念 | 本项目中的含义 |
|---|---|
| 自进化 | 更新经验和版本化方法；不训练模型权重，不自动保证每版更好 |
| Tool | 真正读取数据/产生效果的能力；权限、参数、范围与审批由程序检查 |
| Skill | 触发、步骤、限制、验证、停止条件组成的方法提示，附版本与来源 |
| Experience | 某类执行情境的失败/修正教训，保留轨迹来源，可归纳为 Skill |
| Workflow | 程序定义的控制流；Skill 的 workflow 字段目前不是可执行 DAG |
| Memory | 有任务检查点与跨任务经验/方法记忆；无完整多轮对话和用户偏好记忆 |

**为什么 Skill 不多余：** Tool Calling 决定怎么调用能力，Memory 保存过去；Skill 将可复用程序性知识变成独立的版本、评测和变更对象。它仍然具有 Prompt 属性，价值在结构与治理，不在否认自己是提示内容。

**经验与 Skill 独立：** 生成时检查当前有效经验；生成后依赖冻结来源。经验停用/归档/删除，不自动使已生成 Skill 失效。若来源错误，应复核并停用衍生 Skill。

## 3 必须记住的实现事实

| 主题 | 当前事实 |
|---|---|
| 选择 Skill | none / auto / manual；最多三个不同 Skill 的版本；只向普通任务提供适用生产版 |
| 自动检索 | 权限/范围/数据/模型过滤→标签→512 维字符 n-gram 哈希点积；阈值 0.08；不是 LLM Router |
| 手动绑定 | 固定版本 ID/hash；不可用或超窗明确报错，不静默换版 |
| 生成 | 管理员显式启动；最多 20 条来源经验、每批 1–3 候选；父版、目标、配置和预算冻结 |
| 目标 | correctness / fewer_tools / lower_cost / lower_latency + 人工 guidance；无数值训练目标函数 |
| 发布 | 来源报告必须完整有效，管理员决定质量取舍；生成/评测成功都不自动上线 |
| 配对组 | baseline 无经验无 Skill；experience 仅经验；candidate 仅候选；previous 仅旧生产版（存在时） |
| 原始任务 | 管理评测任务留在数据库/报告，但从普通用户历史与线上使用统计排除 |
| 预算 | 请求前事务预留→usage 结算；未知用量保守保留；全局、任务和批次共同限制 |
| 审批 | 绑定 task + step + tool + arguments；批准后重查权限；处置目前是模拟动作 |
| 恢复 | 应用 JSON 检查点；不明付费请求不自动重发；模拟回执幂等不等于外部 exactly-once |
| Token 默认 | 窗口 1,000,000，输出 32,768，余量 4,096；只是项目配置，非供应商规格证明 |
| 流式 | 只展示 finish.answer 预览；完整 JSON 校验后才接受结果，不流式执行工具 |
| 导出 | SKILL.md + references，portable 替换内部工具名；目标 Harness 仍需能力适配和效果验证 |

**不要混淆：** `SUCCESS`（运行收尾）≠ `completion=complete`（满足要求声明）≠ `answer_correctness=pass`（有参照核验）。引用有效也不等于语义或因果正确。

常规 source/category 评测采用确定性 reference 或 observational；无参照正确性为 unknown。仓库虽有 LLM Judge，当前正常流程未贯通，不应声称开放任务已自动 LLM 评审。

## 4 实验、价值与不足

**V0/V1/V2：** 初始 Skill、第一次修订、第二次修订；应用版本仍为 `0.1.0`，数据库 Skill 版本各自独立。当前图表无法绑定具体版本与原始轨迹。

**数据怎么讲：** 保留 CSV 是人工情景汇总。设定中 V2 质量最高，none 费用/耗时最低；这不能证明真实 V2 优于 V0/V1。真实每组 20 条时，一条就是 5 个百分点；还要看任务配对、未知率和区间。当前 10 个可信示例主要是 8 个业务查询与 2 个合成事故，不是十种完全不同能力。

**指标：** 完成、答案正确、必需工具/替代能力覆盖、逻辑工具数、模型账本请求数、wall latency、费用估计分别报告。未知不能计成功；已核验正确率要同时报告核验覆盖率。线上均分是使用关联，联合 Skill 不能归因到单个版本。

**最大价值：** 模型灵活提议，系统严格执行边界；方法有来源、候选、报告和发布决策。预算预留、精确审批、检查点和版本证据绑定是可具体解释的工程亮点。

**最大不足：** 缺可复核真实效果实验；规则路由/业务假设硬编码；哈希检索和 1000 条截断不适合大库；无语义冲突与自动择优；无完整长对话。业务评测数据 hash 只覆盖部分订单字段，旧评测/Judge 分支残留。已有版本管理和线上统计，不能说完全没有。

**五个优先改进：**

1. 统一线上/评测任务合同、数据指纹、正确/错误/未知口径，保存真实配对原始证据。
2. 给修订生成器具体失败参数、能力缺口、反例和修复依据。
3. 展示与生产版的差异，建议保留退化前版本，保留所有失败候选。
4. 改数据库过滤/索引，再做语义召回、去重、冲突检查和停用建议。
5. 抽象 DomainAdapter / Provider；按业务需要补长对话、可靠 worker 和真实动作幂等。

## 5 二十个高频问题：一句话回答

| # | 问题 | 回答 |
|---|---|---|
| 1 | 什么是自进化？ | 根据反馈生成方法变体，经评估与采用决策影响后续任务。 |
| 2 | 本项目训练模型吗？ | 不训练，变的是经验、Skill 版本及注入上下文。 |
| 3 | 为什么用 Skill？ | 将可复用方法变成有结构、来源、评测和回滚的变更对象。 |
| 4 | Skill 不就是 Prompt？ | 在线确实作为提示，但外层有独立治理与版本管理。 |
| 5 | 经验与 Skill 重复吗？ | 局部教训与整套方法有重叠但用途不同，当前尚缺语义去重。 |
| 6 | Tool 和 Skill 区别？ | Tool 执行能力，Skill 指导何时如何用，不能授权工具。 |
| 7 | Skill 怎么选？ | 先范围与生产状态过滤，再标签和哈希相似度；支持手动最多三个。 |
| 8 | 十万个 Skill 呢？ | 当前扫描不够，要过滤下推、持久索引、召回重排与库治理。 |
| 9 | 生成自动吗？ | 管理员发起受预算约束的生成，LLM 可以执行提炼/修订。 |
| 10 | 评测后为什么不发布？ | 评测只记事实，管理员按有效来源报告独立决定。 |
| 11 | 来源评测必须有答案？ | 不必；没有参照时检查执行和证据，正确性保留未知。 |
| 12 | 旧版还依赖经验条目吗？ | 依赖冻结来源，不依赖活动经验一直启用。 |
| 13 | 有 Memory 吗？ | 有任务状态与长期方法记忆，没有完整对话/用户记忆。 |
| 14 | 长对话怎么加？ | 会话消息、工作状态、带来源摘要、分层检索和遗忘/冲突治理。 |
| 15 | 如何防超预算？ | 数据库事务中预留后调用，实际 usage 结算，未知费用保守记账。 |
| 16 | 权限和审批区别？ | 权限允许请求能力，审批允许这一次具体高风险操作。 |
| 17 | 已完成为何未通过？ | 执行终态、满足要求与答案核验是三个独立判断。 |
| 18 | V2 为什么更好？ | 现存人工情景不能证明，需要冻结版本与逐任务真实配对轨迹。 |
| 19 | 怎么接新业务？ | 复用治理框架，适配数据、工具、路由、权限和独立评价器。 |
| 20 | 为什么不是 toy？ | 用真实边界、失败路径测试和可复核证据说明价值，而不是堆框架和夸大收益。 |

**面试收束句：** 我能解释哪些机制已经工作，也能区分哪些收益尚未被验证；下一步先把评价和真实证据补齐，再按实际业务扩展规模与能力。
